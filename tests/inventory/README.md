# Inventory and solo write guards

Run the application tests with Node 24:
`node --experimental-vm-modules --test --test-reporter=tap tests/inventory/*.test.mjs`

24 application tests execute actual source with allowlisted dependency doubles.
No npm install, credentials, SDK connection or email. These tests cover guard decisions,
successful permitted operations, lookup failures and the 400→480 arithmetic example.
They do not simulate PostgreSQL RLS or concurrency.

Database coverage: `supabase/tests/database/solo_inventory_guards.test.sql` runs
against the disposable Supabase in GitHub Actions, alongside existing authorization
tests. Synthetic fixtures are rolled back. It tests direct writes using service_role,
including upsert bypass attempts and immutable closed solo rows.

Migration: `20260914142358_solo_inventory_write_guards.sql`.
Its filename was generated by Supabase CLI in the disposable runner. It adds a durable
solo started_at marker and invoker triggers in private; it changes no authorization
grants and exposes no privileged RPC. Trigger functions cannot be called as public RPCs.

The durable start marker uses existing counter_name or first entry as evidence.
Session row locks serialize list/count/closure operations. A short transaction advisory
lock coordinates solo lifecycle and BPU edits. No external requests occur under locks.
This version does not include a multi-connection stress test.

Deployment requires explicit approval: review migration, apply it to the intended
database, then merge/deploy the code. Preview currently shares the production database;
a Preview deployment is NOT an isolated database test. No migration was applied to
production by this PR.

Scope limits: these are solo protections and BPU guards during open solo sessions.
Two-administrator team approval, automatic recalculation of persisted team results,
WHS isolation and historical report rendering are separate work. Stored closed solo
quantities are immutable; this is not a claim that every historical report already
snapshots every inventory attribute. See PR #68 for the complete desired behavior.

## Approved import format — PR #70
`import-format.test.mjs` adds 81 pure tests, executed by the existing workflow
without npm, database credentials or network access. Together with the original
24 action tests: 105 passed on ad3b15fb6761bc0693baac179f5cbca42358f0c1.
Run: https://github.com/ycristan/ProjectCountStock/actions/runs/35194500249

Coverage: all 13 required headers and arbitrary order, mandatory values,
optional zeros/blanks, invalid numeric/boolean input, explicit inactive status,
WHS normalization and mixed-WHS rejection, all duplicate candidates,
explicit/stale/forged choices, leading-zero strings, no partial payload,
and export/reimport of the in-memory matrix.

Limits: NOT real XLSX parsing, NOT database/RLS/concurrency tests, NOT proof of
new warehouse confirmation or persisted atomicity. The pure module is deliberately
not wired to the old importer. The XLSX adapter must reject formula/error cells,
preserve formatted identifiers and apply file/resource limits. Future server
actions must rerun validation and enforce authorization; client preview is not trusted.
